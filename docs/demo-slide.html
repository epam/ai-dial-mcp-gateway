MCP Sign-In Gateway for DIAL

The problem. DIAL holds every user's upstream MCP credential (Notion's token) inside Core, per user — as the MCP authorization spec requires — but the only designed way to establish it was DIAL Chat. In a Chat-less deployment, harness users had no way in.

Config-only CoreNo Core code change — the gateway registers as an extra identity provider in settings
Off the data pathMCP traffic flows front door → Core directly; the gateway never sees a payload
Credential containmentThe upstream token and PKCE verifier never leave Core — the gateway transits only a code
Per-user isolationReal sub + roles copied into gateway-minted tokens; every DIAL mechanism works unchanged
Silent repeat useGateway-local refresh with rotation; the identity provider is never contacted after sign-in
Any harnessCIMD (Claude Code) and DCR (Cursor) registration; audited, rate-limited, fail-closed
The compliance shieldConsumes the deployment IdP's MCP incompliances (no CIMD/DCR, quirky claims) — any harness gets a perfectly MCP-compliant AS; apps with MCP endpoints served the same way
Proven: all five PoC-C acceptance criteria closed on real harnesses — Claude Code via CIMD, Cursor via DCR — with the audit trail and Core's logs corroborating every step.
